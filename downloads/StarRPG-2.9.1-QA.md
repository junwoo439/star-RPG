# StarRPG 2.9.1 검증 기록

2026-11-02. Minecraft1.21.1 / NeoForge21.1.235 / Java21. Linux 네이티브 클라이언트, Xorg, Mesa llvmpipe, CPU 할당4코어 환경에서 실행했습니다. 사용자 운영 월드는 열지 않았으며 기존 개발 검증 월드는 복사본으로만 열었습니다.

## UI와 외형

6화면(상점·각성·모험·강화·룬·별 낙하) × 5설정, 총30건을 실제 게임으로 실행했습니다. 854×480/배율4, 640×480/3, 1280×720/4, 1280×800/2, 1920×1080/5입니다. Minecraft 자체의 최소 창 크기에 따른 유효 배율 제한도 적용됩니다.

버튼·슬롯의 화면 경계를 검사했고 축소 좌표의 반지 장착이 서버에 반영됐습니다. 창을 연 상태에서 크기·배율을 변경하고 오른쪽 드래그로 별가루를 세 슬롯에 하나씩 분배했습니다. 커서의 나머지 아이템을 내려놓은 뒤 실제 입력 콜백으로 이동해 툴팁 위치와 내용을 촬영했습니다. 강화 창 설명·버튼의 겹침도 정리했습니다.

53종을 실제 클라이언트에 생성하고 이동 명령·공격 예고·공격·피격·사망을 실행했습니다. 종류별5장, 총265장의 상태 화면을 기록했습니다. 최초 곰의 대기 사진은 청크 표시가 끝나기 전이어서 외형 모음에는 같은 개체의 예고 사진을 사용합니다. 사진 속 소는 공격 표적입니다. 모든 종류의 메시·재질과 CE 용10종의 실제 표시를 확인했습니다. 같은 종족은 기반 관절 구조를 공유합니다.

정점 버퍼 최적화 후에는53종 각각의 기본 자세와 회전·비균일 배율을 적용한 자세를 기존 렌더 계산과 비교했습니다. 총229,424정점의 위치·법선·색·UV·조명이 일치했습니다(좌표·법선 허용 오차0.00002). 기존 리소스400개는 바이트가 동일합니다.

CE 적룡의2·3페이즈는 실제 서버 AI로 비행·공중 공격·착륙을 실행했습니다. 두 페이즈 모두 공중 높이와 종료 후 중력 복원을 확인했습니다. CE 렌더러 활성 로그와 사진을 함께 기록했습니다.

## 전투·저장·통신

자동 GameTest는 CE 포함253개, CE 없는 구성253개를 실행합니다. 기존245개에 화면 좌표·등록 ID/피격 부위·용10종 출현 단계·장신구 수정 감지·이전 보스 NBT·기존 메뉴 JSON 동일성·53종 실제 근접 피해·경로 재사용 검사를 더했습니다. 새53종 검사에서는 예고9틱 동안 피해가 없고10틱째 실제 체력이 줄며 뒤쪽과 사거리 밖의 표적이 제외되는 것을 확인합니다. 기존 검사에는 강공격/스턴/패링·브레스 벽 차단·궁극기·강화/룬 저장·아군 보호와2.9 시스템 회귀가 포함됩니다.

13활성 직업을 전직10단계·무기+25로 실행해 G능력/중복 사용 차단과 실제 근접·화살·마법탄 피해를 확인했습니다. 1·2·4·16명 서버 참여자 구성의52조합이며, 일반 보스 파티 배율은4인 상한과 중복 적용 방지를 검사했습니다. **이 부하 구성은 실제 클라이언트1개와 서버 전용 모의 참여자15명입니다.** 실제16클라이언트의 네트워크 부하 시험을 의미하지 않습니다.

별도로 네이티브 Minecraft JVM2개를 TCP 연결해 파티 초대/수락, HUD, 아군 공격/원소 보호, 의뢰, 제작·장착, 보스/레이드 인원 배율, 치유 기여·개인 보상, 마을/세력·변이/성좌, 공동 던전 완료/개인 보물, 재접속 후 장착/파티 유지를 검사합니다. 실제2클라이언트 구간의 서버 틱803개는 별도 JSONL로 기록했습니다. 중앙값4.532ms,95백분위42.756ms였으며, 던전 생성과 재접속을 포함한 기능 시나리오 전체의 측정입니다.

기존 저장 검사는 다음 개발 월드들의 복사본으로 수행합니다.

| 이전 버전 | 검사 대상 |
|---|---|
| 2.9.0 | 2클라이언트 검증 월드의 인벤토리·아이템 컴포넌트·골드·장신구·성좌·파티·평판/세력·퀘스트/던전 진행을 실제 서버 로딩 결과와 비교하고 정상 저장 종료 |
| 2.5.0 | 기존 선택 직업·전직 단계·숙련/경험/보스 기록을 실제 저장 파일에서 불러와 비교하고 정상 저장 종료 |
| 2.8.0 | 이전 CE 용 검증 월드의 저장된 드래곤이 새 버전에서도 등록·로드·표시되는지 확인하고 정상 저장 종료 |

정상 종료 후 실제 저장 파일도 다시 비교했습니다. 세 복사본의 인벤토리가 원본과 같았고,2.9의 모험·각성·던전 시련·골드 파일,2.5의 직업·골드 파일,2.8의 모험·던전 시련 파일의 논리 NBT가 동일했습니다. 생존 모드 월드의 난이도 시계는 실행한 시간만큼 진행됐습니다.

2.9검증 월드에는 직업 저장 파일이 없으므로 직업 검사는2.5월드로 보완합니다. 이 월드들의 실제 아이템 구성과 별개로 고단계 강화·룬·장비 컴포넌트는 기존 자동 저장 왕복 검사로 검증합니다. 운영 서버의 모든 모드 조합이나 사용자 개별 월드 전체에 대한 검사를 대신하지 않습니다.

## 성능 측정

JFR를 켜고 새 평지 검증 월드에서 네이티브 클라이언트1개와 모의 참여자15명, 동일한 거리·FPS 제한으로 측정했습니다. 각 구간은100틱 준비 후239개 서버 틱을 기록했습니다. 서버 틱 시간은 의도적인 틱 대기를 제외한 계산 시간입니다. 숫자는 아래 조건에서의 단기 관측값입니다.

| 구간 | 이전 중앙값ms | 최종 중앙값ms | 이전95백분위ms | 최종95백분위ms |
|---|---:|---:|---:|---:|
| 대기 | 7.785 | 5.340 | 62.753 | 33.652 |
| 보스1 | 4.055 | 3.252 | 21.675 | 12.965 |
| 몬스터64 | 18.861 | 10.275 | 58.501 | 27.035 |
| 보스4+몬스터64+메뉴 동기화 | 9.348 | 8.182 | 30.655 | 25.812 |

첫 중간 빌드의 마지막 구간은 중앙값11.605ms로 이전보다 느렸습니다. 이후 정점·법선 변환의 임시 벡터 할당을 줄이고 네 구간을 다시 측정했습니다. 중간 결과도 `PERFORMANCE-2.9.1.csv`에 남겨 두었습니다. 최종 밀집 구간에는 최대848.688ms의 긴 틱도 관측됐습니다. JIT·GC·소프트웨어 렌더링·짧은 표본의 변동이 있으므로 일정한 개선율이나 끊김 없는 프레임을 보장하는 수치로 해석하지 않습니다.

장신구3개를 장착한 동일 플레이어를 같은 틱에6000번 읽는 비교에서 기존 파싱은약9.1~9.3MB, 캐시 경로는약0.91MB를 할당했습니다. 순서를 바꾼 반복 비교에서도 결과 아이템 수는 동일했습니다. 초기 빈 장신구 측정은 이 비교의 근거로 쓰지 않았습니다. 전체 서버·클라이언트 프로파일을 바탕으로 반복 경로 요청, 데이터 파싱, 보스바 이름 생성, 반사 메서드 탐색, 정점·법선 임시 객체를 줄였습니다.

클라이언트는 Mesa 소프트웨어 렌더링이므로 게임용 GPU의 FPS 평가가 아닙니다. 실제2클라이언트의 통신 시험과16명 서버 모의 참여자 시험을 구분합니다. Windows Eclipse GUI 자체와 실제16클라이언트 접속은 이번 실행 범위에 포함되지 않습니다.

## 재실행과 배포 검사

일반 빌드는 `gradlew.bat build`, 서버 자동 검사는 `gradlew.bat runGameTestServer`입니다. 개발용 외부 모드 설치는 `installAdventureMods` 태스크를 사용합니다. 소스의 `tests` 패키지와 검증용 구조물은 배포 JAR에서 제외합니다. UI/부하/이전 월드/두 클라이언트 자동 실행은 명시적 Gradle QA 속성으로만 활성화하며, 일반 Eclipse 실행 설정에는 포함하지 않습니다. QA 촬영·프로파일 경로는 이 Linux 실행 환경에 맞춰져 있습니다.

최종 설치 ZIP은 여덟 JAR 해시·ID, 반복 설치, 기존 JAR 보관, 충돌 시 복구, 잘못된 원격 해시 거부, 패키지 압축 해제 후 재설치를 검사합니다. 소스 ZIP과 JAR/매니페스트의 일치, JSON 파싱, 테스트 코드 및 외부 CE 자산 미포함, 일반 IDE 인자의 QA 속성 제거도 확인합니다.
